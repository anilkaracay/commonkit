# PILOT — real users, in two layers (D-024)

Status: **not run; deferred until after the hackathon.** The kit below (app page `/app/pilot`, QR sheets, runbook) is ready; no pilot numbers are claimed anywhere. Judges never need hardware: the full demo still runs on emulators and the simulator (D-022).

| Layer | What | Adapter | Label everywhere |
| :--- | :--- | :--- | :--- |
| (a) Real users | A real shared item (chosen by the human, H1), lent by a steward to real members who reserve on testnet | `manual_qr` (no electronics: the steward hands the item over for a confirmed reservation and confirms the return) | "pilot" + the real numbers |
| (b) Real plug, stand-in load | One real smart plug (Shelly Gen2/Gen3 or Tasmota, model TBC, H2) powering a desk lamp or kettle that stands in for a machine; used for the video | `smart_plug` | "stand-in" (the lamp is not the machine) |

Who does what on the day: `pilot/RUNBOOK.md`. Printable QR sheets: `pilot/qr/<alias>.pdf`, generated by `scripts/pilot/qr-sheets.ts`.

The README reports the real numbers, whatever they are, each with tx links. A missed target is stated as missed. Never inflate; never count team test accounts as pilot members.

## 2. Accounts, funding and data

- Each participant creates their own testnet account in a wallet on their own phone (H5 checks the wallet flow first). We never hold their keys.
- The participant list (account ids only, no names, phone numbers or e-mails) lives only in `pilot/participants.local.json`, which is gitignored (`pilot/.gitignore`). Consent replies stay in the chat and, if saved, in the gitignored `pilot/consents/`.
- Funding: `scripts/pilot/fund-participants.ts` (chain-ops) sends 2 testnet NEAR to each consenting participant listed in `pilot/participants.local.json` and logs the tx hashes to evidence. Nobody is funded before they consent.
- What goes into git: tx hashes, counts, item name, asset account, lowered thresholds. Account ids appear only where the chain already shows them (tx evidence). No names, photos or messages.
- Evidence photos (item condition, upkeep before/after) stay on the phone; only their sha256 goes on chain (`evidence_hash`, `note_hash`).

## 5. Lowered pilot thresholds (labelled)

The pilot item's profile thresholds (or `every_hours`) are lowered so an upkeep task can come due within the pilot. They are set by a DAO `set_profile` proposal (tx in evidence) and the README states them next to the production values from `profiles/*.json`, for example: "Thresholds were lowered for the pilot so an upkeep task could come due within the pilot day; production values are in profiles/<file>.json." The same applies to the demo assets' `meta.pilot_overrides`.

## 6. Data to capture

- Every tx hash (scripts and web app log them to `evidence/pilot/*.json`): reservations, `confirm_return`, task open / claim / submit / approve, rights minted, fault reports.
- Counts for §1, computed from those txs.
- Offline fallback entries (RUNBOOK §4), each labelled "entered later from the paper log" with the original time.
- One short written quote from a participant, only with explicit permission to publish.
